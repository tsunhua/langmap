# 詞句詳情頁與對照圖譜優化規格

**日期：** 2026-07-26  
**狀態：** Implemented  
**範圍：** `web_v2` 詞句詳情頁、對照圖譜及其後端查詢  
**目標頁面：** `/mapping/:id`  
**驗證樣本：** `/mapping/1146386197`

## 1. 背景

詞句詳情頁目前使用固定尺寸的徑向圖顯示對照關係。根詞句位於中心，所有一跳與二跳節點都被均勻放置在同一個固定半徑上。

這個模型在節點數較少時可以快速表達「中心詞句與其他詞句相連」，但無法承載實際資料密度，也不能正確表達二跳以上的關係來源。

本次改造保留 LangMap 現有 Atlas 紙張感、暖色背景、陶土色主色與藍色關係線，不更改頁面路由與主要資訊架構。設計重點是：

1. 關係層級清楚。
2. 節點不互相遮擋。
3. 圖譜可以平移、拖曳及縮放。
4. 大量資料仍可探索。
5. 桌面與行動裝置都有可用的替代操作方式。

建議設計參數：

- 視覺變化：5/10
- 動效強度：3/10
- 資訊密度：7/10

這是一個資料探索介面，不需要裝飾性動畫或大幅更換視覺語言。

## 2. 現況診斷

### 2.1 實際頁面觀察

以 `/mapping/1146386197` 為樣本：

- 一跳包含 40 個映射節點，加上根節點共 41 個節點。
- 桌面圖譜顯示區約為 `808 × 465px`。
- 41 個節點全部涉及重疊，共檢測到約 100 組節點碰撞。
- 展開二跳後共 103 個節點，其中 62 個為間接節點。
- 二跳節點仍然從根節點直接畫出虛線，無法看出它是透過哪個一跳詞句被發現。
- 390px 寬的行動版中，圖譜實際尺寸約為 `287 × 165px`，文字與節點無法有效閱讀或操作。

### 2.2 前端限制

現有 `RadialGraph.vue`：

- 使用固定 `800 × 460` viewBox。
- 所有節點使用固定半徑 `175`。
- 每個節點僅依陣列索引平均分配角度。
- 沒有測量節點實際寬高。
- 沒有碰撞檢測。
- 沒有平移、縮放、觸控手勢與節點拖曳。
- 一跳與二跳共用同一圈節點座標。
- 二跳連線固定從根節點開始。
- 每張節點卡片包含隱藏式投票元件，增加 DOM 成本與互動衝突。

### 2.3 後端限制

現有 `GET /expressions/:id/mappings`：

- 回傳扁平節點陣列，沒有完整邊集合。
- 二跳節點只有 `hops: 2`，沒有 `source_id` 或父節點資訊。
- 二跳的 `edge_id` 被設為 `null`。
- 查詢參數允許最大 3 跳，但實際只計算到 2 跳。
- 無法表示多父節點、交叉關係或完整探索路徑。
- 缺少節點總量、每層數量及截斷狀態。

前端不能只靠目前的回傳資料推導正確的層級樹。後端資料契約必須先調整。

## 3. 產品目標

### 3.1 核心目標

- 初始佈局不存在節點重疊。
- 二跳節點顯示在其一跳來源節點外側。
- 三跳節點顯示在其二跳來源節點外側。
- 使用者可以拖動節點。
- 使用者可以平移、放大及縮小整張圖。
- 使用者可以快速回到自動佈局或適應畫面。
- 大量節點可以漸進展開，而不是一次全部塞進圖譜。
- 圖譜與下方列表互相定位及同步選取。

### 3.2 非目標

本階段不包含：

- 修改 `/mapping/:id` 路由結構。
- 更換整站設計系統。
- 將圖譜改成 3D 或 WebGL。
- 將使用者拖曳座標永久保存到後端。
- 完整圖資料編輯功能。
- 在圖譜中直接建立或刪除映射。

## 4. 關係展示模型

### 4.1 徑向層級圖

預設繼續使用徑向圖，避免與現有頁面產生過大的認知差異，但將固定放射圖改為徑向層級圖：

```text
                         三跳
                           ○
                           │
                   二跳 ○─○
                         │
根節點 ●───────────────○ 一跳
                         │
                   二跳 ○─○
```

佈局規則：

1. 根節點固定在世界座標中心。
2. 一跳節點位於第一層環。
3. 每個一跳節點擁有自己的角度區段。
4. 二跳節點只排列在其展示父節點的角度區段內。
5. 三跳節點繼續排列在二跳節點外側。
6. 子樹越大，獲得的角度區段越大。
7. 每層環半徑根據節點實際尺寸和數量動態計算。
8. 佈局結果必須穩定，相同資料不能因重新載入而大幅換位。

### 4.2 多父節點與循環

資料本質上是圖，而不是嚴格的樹。一個詞句可能由多個上層詞句連到，也可能形成循環。

展示規則：

- 使用受限 BFS 建立展示樹。
- 節點第一次被發現時的來源作為 `display_parent_id`。
- BFS 的鄰接節點必須使用穩定排序。
- 後續發現的其他父關係保留為 `cross_edges`。
- 交叉邊預設不顯示。
- 選取節點時才顯示與該節點直接相關的交叉邊。
- 循環不能生成重複展示節點。
- 側邊資訊面板需要標明「另有 N 條關係」。

### 4.3 邊的視覺語意

- 展示樹主邊：藍色實線。
- 二跳及三跳：顏色逐層降低對比，但仍使用實線。
- 交叉邊：只在選取時出現，可使用細虛線。
- 選取路徑：提高對比及線寬。
- 非相關分支：降低至約 20%-30% 不透明度。
- 邊線寬可表達評分，但不能是唯一的評分訊號。
- 不再從根節點向所有二跳節點畫虛線。

## 5. API 資料契約

### 5.1 建議回傳格式

`GET /api/v2/expressions/:id/mappings?hops=2`

```ts
interface MappingGraphResponse {
  root_id: number
  requested_hops: 1 | 2 | 3
  resolved_hops: 1 | 2 | 3
  nodes: MappingGraphNode[]
  edges: MappingGraphEdge[]
  layer_counts: Record<number, number>
  truncated: boolean
  omitted_count: number
}

interface MappingGraphNode {
  expression_id: number
  text: string
  language_code: string
  language_name: string
  depth: number
}

interface MappingGraphEdge {
  edge_id: string
  source_id: number
  target_id: number
  score: number
  depth: number
}
```

說明：

- `nodes` 只保存詞句資料。
- `edges` 保存實際關係，不把關係資訊混入節點。
- `depth` 表示從根節點出發的最短距離。
- `edge_id` 必須保留，讓所有可投票關係都有實際目標。
- `source_id` 和 `target_id` 不要求代表資料庫中的原始 A/B 順序，只需代表本次遍歷方向。

### 5.2 查詢規則

- 最小跳數為 1，最大跳數為 3。
- 使用遞迴 CTE 或後端受限 BFS。
- 每次遍歷記錄已訪問節點，避免循環。
- 鄰接關係使用以下順序穩定排序：
  1. 評分降序。
  2. 語言代碼升序。
  3. 詞句文字升序。
  4. 詞句 ID 升序。
- 建議總節點上限為 150-200。
- 建議各深度可另外設定上限。
- 達到上限時回傳 `truncated: true` 及 `omitted_count`。
- 不允許 UI 宣稱支援 3 跳，而 API 只回傳到 2 跳。

### 5.3 相容策略

可選擇以下其中一種策略：

1. 直接升級現有 endpoint，前後端同步發佈。
2. 新增 `/expressions/:id/graph`，保留舊 endpoint 給其他客戶端。

若目前沒有其他客戶端依賴舊格式，建議直接升級現有 endpoint，避免維護兩套語意相近的 API。

### 6.2 狀態分層

資料狀態：

- 根詞句。
- 節點與邊。
- 展示樹。
- 各層數量。
- 截斷資訊。

檢視狀態：

- 當前 zoom transform。
- 選中節點。
- 展開及收合的分支。
- 使用者拖曳後的位置覆寫。
- 語言及評分篩選。
- 顯示跳數。

檢視狀態不應混入 API 回傳物件，以免重新取資料時覆蓋使用者操作。

### 6.3 佈局演算法

`mappingGraphLayout.ts` 必須是可測試的純函式：

```ts
interface LayoutInput {
  rootId: number
  nodes: MappingGraphNode[]
  edges: MappingGraphEdge[]
  nodeSizes: Map<number, { width: number; height: number }>
  collapsedNodeIds: Set<number>
}

interface LayoutOutput {
  nodes: Array<{
    id: number
    x: number
    y: number
    depth: number
    displayParentId: number | null
  }>
  treeEdges: MappingGraphEdge[]
  crossEdges: MappingGraphEdge[]
  bounds: { x: number; y: number; width: number; height: number }
}
```

建議流程：

1. 建立鄰接表。
2. 以 BFS 產生穩定展示樹。
3. 計算每個節點的可見子樹權重。
4. 依子樹權重分配角度區段。
5. 根據每層節點寬高計算環半徑。
6. 放置節點。
7. 執行有限次碰撞修正。
8. 重新計算邊端點與世界座標 bounds。

碰撞修正不能使用永久運行的力導向模擬。佈局應在資料或節點尺寸改變時執行一次，完成後保持穩定。

### 6.4 第三方依賴

目前專案沒有圖譜佈局或縮放依賴。建議只安裝必要的 D3 子套件：

```bash
npm install d3-hierarchy d3-zoom d3-drag
npm install -D @types/d3-hierarchy @types/d3-zoom @types/d3-drag
```

用途：

- `d3-hierarchy`：層級與子樹計算。
- `d3-zoom`：滑鼠、觸控與工具列縮放。
- `d3-drag`：節點拖曳。

不建議引入完整 `d3` 套件，也不建議預設使用 `d3-force`。

## 7. 圖譜操作

### 7.1 畫布操作

- 滑鼠滾輪縮放。
- 觸控板平移與縮放。
- 雙指觸控縮放。
- 拖曳背景平移。
- 工具列放大及縮小。
- 適應畫面。
- 回到 100%。
- 重置自動佈局。
- 縮放範圍建議為 25%-250%。

圖譜所有線條與節點必須共用同一個 world transform。縮放時只更新父層 `transform`，不得逐節點更新 Vue 響應式座標。

### 7.2 節點操作

- 點擊：選取節點並打開資訊面板。
- 雙擊或資訊面板按鈕：進入該詞句詳情。
- 拖曳：移動單一節點，相關邊即時跟隨。
- 拖曳結束後保留本次工作階段位置。
- 重置佈局時清除所有使用者位置覆寫。
- 拖曳距離超過閾值後，不得觸發點擊或頁面跳轉。
- 鍵盤 Enter 或 Space 可選取節點。
- Escape 取消選取。

### 7.3 漸進展開

全域切換二跳可能一次加入大量節點，因此需要分支級控制：

- 一跳節點顯示可展開子節點數，例如 `+12`。
- 點擊展開控制，只顯示該節點的下一層。
- 可單獨收合分支。
- 工具列提供「展開所有二跳」。
- 大型分支先顯示前 N 個節點及一個聚合節點。
- 聚合節點顯示「另外 N 個」。

全域跳數表示最大允許深度，不代表所有分支必須同時展開。

### 7.4 語意縮放

不同縮放比例使用不同資訊密度：

- `< 45%`：短文字或語言標記，不顯示次要資訊。
- `45%-80%`：顯示詞句及語言代碼。
- `> 80%`：顯示完整節點卡片、評分與子節點數。

過長詞句在圖譜中截斷，完整文字放在資訊面板和列表。

## 10. 行動版

行動版不能只縮小桌面圖譜。

### 10.1 頁面結構

- 提供「圖譜 / 列表」切換。
- 預設可根據產品判斷選擇列表或圖譜。
- 圖譜接近全寬。
- 圖譜高度至少約 `55dvh`。
- 節點資訊使用底部抽屜。
- 工具列固定在圖譜底部或右下角。
- 所有觸控目標至少 44px。

### 10.2 手勢

- 單指拖曳背景平移。
- 雙指縮放。
- 單指拖曳節點移動節點。
- 節點拖曳與畫布平移必須有清楚的命中區域。

### 10.3 簡化節點

- 預設只顯示短文字與語言代碼。
- 不在節點上顯示投票控制。
- 長詞句在底部抽屜顯示全文。
- 低縮放比例可進一步簡化為標記點和短標籤。

## 11. 載入、錯誤與空狀態

### 11.1 載入

- 使用符合圖譜外形的骨架。
- 保留圖譜容器高度，避免 CLS。
- 切換跳數時保留已有節點，只對新增分支顯示載入狀態。

### 11.2 錯誤

- 首次載入錯誤顯示完整錯誤狀態與重試按鈕。
- 展開分支失敗只在該分支顯示錯誤，不清空整張圖。
- 保留已經成功載入的節點。

### 11.3 空狀態

- 保留「尚無對照映射」。
- 提供明確的「添加映射」操作。
- 不渲染空白圖譜容器。

## 12. 無障礙

- 圖譜提供可理解的 `aria-label`。
- 節點可透過鍵盤聚焦。
- Enter 或 Space 選取節點。
- 鍵盤使用者可透過層級列表完成所有核心操作。
- 縮放控制具有文字標籤或清楚的 `aria-label`。
- 評分不能只靠線寬或顏色表達。
- 選取、展開、收合狀態要暴露給輔助技術。
- 所有動畫尊重 `prefers-reduced-motion`。
- 高亮和低對比狀態仍需維持必要的文字對比度。

## 13. 效能

目標：

- 150 個節點時平移與縮放保持順暢。
- 縮放與拖曳不觸發整棵 Vue 元件樹每幀重繪。
- 不在 pointer move 中寫入高頻 Vue 響應式狀態。
- 只動畫 `transform` 和 `opacity`。
- 節點投票元件按需渲染。
- 圖譜離開頁面時移除所有事件監聽器。
- ResizeObserver、D3 zoom 和 drag 行為必須正確清理。

如果未來節點上限超過 200，再評估 Canvas 或 WebGL。本階段 SVG 邊層配合 HTML 節點層已足夠。

## 14. URL 與狀態保存

建議將可分享的檢視狀態放入 query：

```text
/mapping/1146386197?hops=2&lang=en-US&node=1537277351
```

可保存：

- 最大跳數。
- 語言篩選。
- 選中節點。

不建議保存：

- 每個拖曳節點的座標。
- 即時縮放 transform。
- 暫時 hover 狀態。

## 19. 風險與決策

### 19.1 圖與樹的差異

關係資料不是嚴格樹狀。必須明確區分：

- 真實圖資料。
- 為了可讀性生成的展示樹。

不能在後端丟棄交叉邊，也不能同時把所有交叉邊預設畫出。

### 19.2 一次展開過多節點

單純解決重疊並不足夠。若仍一次顯示 100 個完整卡片，初始 fit-to-view 會使文字太小。漸進展開和語意縮放是必要功能，不是後續裝飾。

### 19.3 拖曳與點擊衝突

節點同時具有選取、跳轉和拖曳功能。實作時必須使用位移閾值區分 click 與 drag，不能依賴單純的 click suppression。

### 19.4 D3 與 Vue 狀態衝突

D3 只負責幾何、縮放和拖曳，不應接管整個 DOM。Vue 負責節點渲染與應用狀態，D3 負責高頻 transform。

### 19.5 行動版密度

行動版不可能同時讓 100 個完整節點清楚可讀。必須接受語意縮放、分支收合和列表優先的產品策略。

## 20. 最終決策摘要

- 保留徑向視覺，但改為徑向層級佈局。
- 後端回傳完整節點與邊。
- 使用穩定 BFS 建立展示父子關係。
- 多父關係保留為按需顯示的交叉邊。
- 節點尺寸參與佈局，初始碰撞數必須為 0。
- 支援節點拖曳、畫布平移、滾輪與觸控縮放。
- 二跳及三跳顯示在所屬父節點後方。
- 使用分支級漸進展開，避免一次展示所有節點。
- 桌面使用圖譜加資訊面板。
- 行動版提供圖譜和層級列表兩種完整入口。
- 優先完成資料契約與佈局測試，再進行互動和視覺改造。
