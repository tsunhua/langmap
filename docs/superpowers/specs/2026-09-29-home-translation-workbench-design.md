# 首頁整合詞句翻譯工作台

> 日期：2026-09-29
>
> 狀態：設計已通過；2026-09-30 首頁與翻譯工作台版面調整完成，524 個介面詞條的五語系檢查與前端建置通過；正式部署至 `langmap.io`（Worker version `43b5cadf-37e1-4e10-98ca-28f50a61c655`）。已回讀確認搜尋模式含動態、翻譯模式不含動態，390×844 行動首頁頂部間距緊湊，搜尋按鈕獨立位於輸入框下方；來源和目標選單均顯示名稱與代碼，目標清單也能以語言名稱查找。AI 端到端與隔離 PostgreSQL 整合測試仍未驗證。
>
> 參考：[Google 翻譯範例](https://translate.google.com/details?sl=zh-TW&tl=en&text=%E4%BD%A0%E5%A5%BD&op=translate)

## 目標

- 將首頁現有的最新動態改為簡潔的搜尋／翻譯入口；品牌名稱由導覽列承擔，不重複加入長標題與副標題。
- 首頁提供「搜尋」和「翻譯」兩個分頁，預設搜尋；兩種操作都從首頁開始。
- 搜尋結果沿用既有 `/search`；翻譯結果留在首頁，不跳到另一個翻譯頁。
- 搜尋列整合語言選擇、放大的輸入欄與置中的搜尋按鈕；翻譯沿用 Google 翻譯的原文／譯文雙欄與語言操作，並沿用 LangMap 的視覺 tokens 和詞典關係能力。
- 讓訪客能使用翻譯；翻譯結果投稿仍使用既有登入與貢獻流程。

## 已核對的現況與契約

- `/` 目前使用 `HomeFeed.vue` 載入並顯示最新動態；`/search` 使用 `Search.vue`；`/translate` 使用 `ExpressionTranslation.vue`。
- `TopNav.vue` 的桌面導覽與行動抽屜目前沒有首頁項目；頂部搜尋只在 `/search` 以外顯示。
- 搜尋頁必須有搜尋語言才會執行查詢；查詢可透過 `/search?q=...&lang=...` 帶入。
- 翻譯目前由 `TranslationForm.vue` 收集來源語言、文字和目標 locale；`TranslationResult.vue` 提供複製、重試、替代譯法與詞句參考。
- 翻譯 API 目前要求登入，輸入上限為 500 graphemes。`/translate` 頁面也把未登入者導向登入。
- 翻譯是暫態操作；詞句只有在使用者明確提交既有貢獻流程時才寫入資料。

## 方案選擇

1. **採用：首頁搜尋／翻譯分頁。** 預設顯示置中的語言選擇、詞句輸入和搜尋按鈕；切換「翻譯」後在原地顯示既有雙欄工作台。搜尋表單將文字與已選語言帶入既有搜尋頁。各模式只掛載自己的表單，避免共享兩種操作不相同的驗證狀態。
2. **單一輸入、多個動作。** 以完整翻譯工作台承載搜尋按鈕會讓首頁預設顯示語言選擇、譯文面板等非搜尋所需控制，與使用者希望 Google 搜尋式簡潔首頁的需求不符，因此採用分頁。
3. **保留獨立翻譯頁，只從首頁預填內容。** 這是現有路徑的最小改動，但翻譯會離開首頁，與最新確認不符，因此不採用。

## 後續 UI 調整

- 使用者回饋首頁搜尋也需要語言選擇，取代原規格中「搜尋頁再選語言」的決定；目前重用 `ExpressionSearchControls`，未選語言時提示並聚焦選擇器，提交以 `q` 和 `lang` 前往既有搜尋頁。
- 移除可見標題與副標題，以螢幕閱讀器標題保留頁面名稱；Search／Translate 改為明確的分段按鈕，兩種模式保持同一垂直錨點。
- 搜尋列使用單一控制列，搜尋按鈕以 flex 居中；行動版語言、輸入與按鈕另排以維持 44px 以上觸控目標。
- 語言清單中 Arabic／Pushto 的英文 canonical name 取自 ISO 639-3；`ara`、`pus` 的 code-keyed overlay、API 回應及 importer 共用該來源。

### 使用者回饋收斂（2026-09-30）

- 首頁背景沿用全站暖紙張點陣，不加不透明首頁底板；搜尋與翻譯表單、譯文結果直接置於點陣背景上。頁面容器保持透明，輸入框與語言選擇保留實底和邊線，以清楚區分可操作欄位。
- Search／Translate 分頁改為無底色文字與細底線選取狀態，避免膠囊底板和整塊反白。
- 搜尋與翻譯模式各自提供可見標題和簡短操作說明，讓使用者一眼知道要輸入什麼。
- 搜尋模式保留必要的語言選擇，語言選擇獨立排在上方；搜尋輸入橫跨內容寬度並加高，搜尋按鈕移到輸入框下方置中，不與輸入框接成同一列。行動版同樣維持單欄，按鈕獨佔一行。
- 翻譯模式收斂為來源語言、目標 locale、文字輸入與翻譯按鈕；送出後才在按鈕下方出現譯文。點擊譯文中的詞句顯示其直接關聯 mapping；不顯示其他翻譯操作面板。
- 依最新指示，原首頁動態恢復在搜尋框下方，只掛載於搜尋模式；翻譯模式不載入動態。

## 首頁與導覽

- `/` 以簡介和「搜尋／翻譯」分頁取代動態 feed；搜尋為預設模式，顯示單一搜尋框和搜尋按鈕，首頁不再載入動態資料。
- 在桌面導覽及行動抽屜加入「首頁」項目，位於目前主要導覽項目前方；目前路由為 `/` 時呈現 active state。
- 頂部搜尋框只在首頁隱藏；其他頁面提供搜尋入口。桌面搜尋結果頁使用頂部搜尋框；960px 以下沿用行動導覽，搜尋頁使用頁內搜尋欄，抽屜不再重複該表單。語言必選提示必須留在可見區域。
- 首頁成為翻譯的主要入口，移除獨立「翻譯」導覽項目。舊 `/translate` 直接路徑回到首頁，避免維護第二份翻譯介面。
- 沿用 `web/src/assets/atlas.css` 的暖紙張背景、陶土色主色、藍色關係線及現有低圓角 tokens；不新增另一套顏色、陰影或圓角。

## 首頁工作台與互動

- 搜尋分頁只提供一個置中的輸入框與搜尋動作；不顯示來源／目標語言選擇器或全站頂部搜尋框。
- 翻譯分頁在首頁原地呈現既有翻譯工作台，保留來源／目標選擇、結果串流、錯誤及重試行為；不顯示工作台內多餘的搜尋動作。
- 分頁按鈕支援鍵盤左右方向鍵與 Home／End，預設焦點與選取狀態為搜尋。
- 桌面版左右排列來源與結果，行動版上下排列。面板隨內容自然增高，以頁面捲動為主，不增加兩套獨立捲動區；長詞句不撐破版面。
- 來源側保留來源語言選擇與自動偵測、可編輯文字、字數／長度提示和清除操作；沿用 API 的長度驗證與錯誤呈現。
- 結果側提供目標 locale 選擇，兩側均可手動更改語言。來源是 language、目標是精確 locale，不能直接互換；本次不加入需要猜測來源 locale 的一鍵交換。訪客只能選擇既有 locale，建立 locale 沿用登入權限。
- 使用者按「翻譯」後，在首頁右側顯示生成狀態及譯文串流；不對每次輸入自動呼叫 AI。保留取消、重試和編輯來源文字的能力。
- 結果完成後保留既有的複製、exact／AI 狀態、替代譯法、詞句關聯與來源證據操作。投稿只對登入者提供；替代譯法與證據不偽裝成模型已採用的詞義。
- 新翻譯、來源／目標 locale 變更或取消時，舊結果不得覆蓋新狀態；沿用既有請求取消與回應競態處理。
- Google 翻譯只作版面與操作參考。本次不新增音訊、收藏、分享或評分等未有 LangMap 能力支援的操作。

## 查詢流程

- 在搜尋分頁按 Enter 或「搜尋詞句」導向既有 `/search`，把搜尋框文字編碼成 `q`；首頁不猜測 `lang`。
- 查詢只要求非空文字，不要求目標 locale，也不套用翻譯專用的 500 graphemes 上限。
- 不從詞面猜測搜尋語言。沒有提供 `lang` 時沿用搜尋頁既有的最近語言選擇；沒有可用語言時，保留文字並顯示語言必選提示。明確指定但無可搜尋內容的語言，不默默改成另一種語言。
- 離開首頁進入其他頁時顯示頂部搜尋欄。使用者可繼續使用頁面既有搜尋控制，不新增另一套搜尋 API 或結果模型。

## 訪客使用與請求保護

- 移除翻譯頁面和 `POST /api/v2/translate` 的登入門檻；翻譯表單與結果可供訪客使用。
- 對匿名翻譯請求按來源 IP 設定 Cloudflare Worker 突發限流：每 60 秒最多 10 次。這是降低單一來源突發濫用的控制，不是精確費用上限或全域流量配額。
- 維持 500 graphemes 的文字上限、請求 body 上限、來源／目標 locale 驗證、失敗與取消處理。Rate limit 回應使用現有 API 錯誤 envelope，前端顯示可理解的重試提示。
- 超限回應為 `429 / RATE_LIMITED`，提供 `Retry-After: 60`；限流服務缺失或失敗回 `503 / TRANSLATION_UNAVAILABLE`，不繞過限流呼叫翻譯。兩者都保留輸入且不快取。
- 登入者仍可翻譯；只有寫入 contribution 的操作要求登入。匿名請求的 rate limit key 使用 Worker 可取得的客戶端 IP；不得把原文、譯文或 token 寫入 log。

## 範圍與非目標

- 前端：首頁、全站導覽、搜尋帶入、翻譯表單／結果整合、翻譯狀態與相關 i18n。所有 `en.ts` 訊息 key 都需存在於 canonical UI locale CSV，並提供簡中、繁中、英文、日文及西班牙文；翻譯 API 錯誤碼轉成對應的本地化訊息。
- 後端：公開翻譯 API 的授權檢查調整及 Worker rate limit binding/configuration；同步 API 型別與相關契約測試。
- 不修改 `apple/`，不改詞句、edge、locale schema，不新增翻譯歷史或持久化，不擴充翻譯供應商，不增加音訊能力。
- 搜尋頁現有語言必選契約不變；首頁帶入 `q`，不新增跨語言搜尋範圍或新的搜尋排名行為。

## 驗收準則

- 首頁不再請求或顯示最新動態；桌面與行動導覽都能回到首頁並顯示 active state。
- 首頁不顯示頂部搜尋；非首頁路由均有搜尋入口。搜尋頁桌面使用頂部搜尋、行動版使用頁內搜尋，沒有重複表單或被隱藏的必選提示。
- 首頁輸入文字後，查詢會帶入 `/search`，語言可用時保留語言；語言缺少時搜尋頁清楚提示且文字不遺失。
- 首頁翻譯不改變 pathname；桌面雙欄、行動堆疊；翻譯內容逐段顯示在原頁，且結果、複製、重試、替代譯法、詞句參考與登入投稿都依現有契約運作。
- 未登入訪客可成功使用翻譯；超過 per-IP burst cap 的請求得到可理解的限流狀態，登入使用者仍可翻譯。
- 輸入錯誤、空白、超長內容、取消、切換語言及快速連續送出不會留下舊譯文或讓新請求被晚到回應覆蓋。
- 所有互動支援鍵盤、可見 focus、accessible name 與至少 44px 觸控目標；遵守 reduced motion；沒有水平溢出。
- 所有 `en.ts` 訊息 key 都能在五種 locale 取得非空文案；英文來源與 CSV 一致，訊息插值 placeholder 保留。
- 英文 UI 的語言清單使用 registry 提供的 canonical English 名稱；不從一般詞句 mapping 猜測英文標籤，避免 `jpn` 顯示成 `Day` 等同形詞錯誤。
- 前端建置成功，並以桌面及行動 viewport 回讀實際首頁與翻譯結果流程；相關後端測試涵蓋訪客授權和 rate limit 契約。
