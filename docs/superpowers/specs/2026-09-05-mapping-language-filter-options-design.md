# Mapping 語言過濾器可用選項設計

日期：2026-09-05  
狀態：已確認，待實作

## 目標

Mapping 詳情頁的語言過濾器只列出目前跳數範圍內實際出現的語言，並依各語言的詞句節點數量由多至少排列，讓使用者不會選到目前圖譜不可達的語言。

本次只修改前端。不改動 `target_language` 的 API 契約、後端遍歷方式或「根語言與目標語言交替展開」語義。

## 選項範圍與排序

- 選項來源是目前 expression、目前跳數及目前 locale hints 所取得的未過濾圖譜。
- 統計 `depth >= 1` 且 `depth <= requested_hops` 的唯一詞句節點；根節點不計入。
- 依 `lang_code` 分組，每個唯一節點計為一個詞句。
- 先按詞句數降序排列；同數量時按顯示語言名排序，最後按語言代碼排序，確保結果穩定。
- 若圖譜已達 200 節點上限，數量表示實際返回、可顯示的詞句數，不宣稱是所有理論可達節點的總數。

## 資料流程

Mapping 詳情頁保留兩個角色不同的圖譜狀態：

1. 顯示圖譜：沿用現有請求，可帶 `target_language`。
2. 選項來源圖譜：同一 expression 與跳數，但不帶 `target_language`。

沒有選取語言時，同一份未過濾圖譜同時負責顯示與產生選項，不增加請求。已有過濾條件且頁面首次載入或切換跳數時，平行取得顯示圖譜與未過濾圖譜。新增或移除部分過濾條件時，若選項來源圖譜仍符合目前 expression、跳數與 locale hints，只重新取得顯示圖譜。移除最後一個條件時，可直接以選項來源圖譜恢復顯示。

所有請求沿用頁面既有的 request sequence 防護；舊 expression、舊跳數或舊過濾條件的遲到結果不得覆寫目前狀態。

## 元件行為

`LanguageSelect` 接受由頁面提供的可用語言選項，每項包含語言代碼、顯示名稱及詞句數。

- 聚焦或展開空白輸入框時立即顯示全部可用選項。
- 可在前端以語言顯示名或代碼搜尋，不再向全域 language registry 搜尋任意語言。
- 已選語言不重複出現在候選列表。
- 選項顯示語言名、語言代碼與詞句數。
- 鍵盤上下鍵、Enter、Escape、可見 focus、combobox／listbox 關係與至少 44px 的觸控目標維持可用。
- 從 URL 載入但目前不在可用選項中的語言仍保留為已選標籤，使用者可以移除；系統不靜默改寫分享連結的篩選條件。

## 錯誤與空狀態

- 顯示圖譜失敗時沿用目前錯誤提示與舊圖譜回退行為。
- 選項來源圖譜失敗時不以全域語言列表替代；過濾器顯示空候選，但保留已選標籤，避免提供不符合目前跳數的選項。
- 目前跳數沒有相關詞句時，候選列表為空。

## 驗收與測試

- 不同語言的節點依詞句數降序顯示；相同數量使用穩定次排序。
- 根節點不計入，較深但未超過目前跳數的節點會計入。
- 空白查詢可直接看到可用語言，輸入名稱或代碼可本地縮小結果。
- 選取語言後，其他來自未過濾圖譜的選項與原始計數不消失。
- 切換跳數後重新計算相應範圍的選項；遲到請求不覆寫較新的跳數結果。
- 深連結中的不可達已選語言仍可見且可移除。
- 執行相關 Vitest 測試與 `cd web && npm run build`。
