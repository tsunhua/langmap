# 置中搜尋工具列與語言篩選設計

## 狀態

- 日期：2026-09-05
- 狀態：已核准設計，尚未實作
- 適用範圍：LangMap Web 導覽列與詞句搜尋頁

## 背景

目前導覽列的詞句搜尋位於右側操作區，搜尋框本身沒有語言選擇器。送出後，`/search` 頁必須另外取得語言；頁面雖已保存近期搜尋語言，但導覽列、行動版抽屜與搜尋頁並未形成一致的搜尋控制與排序規則。

本改動要讓詞句搜尋成為導覽列的視覺中心，並在所有詞句搜尋入口提供相同的單一語言篩選。語言選項只包含至少有一筆詞句的語言，最近選過的三種置頂，其餘按名稱穩定排序。

## 目標

1. 桌面導覽列的詞句搜尋工具列以視窗為基準置中。
2. 導覽列、行動版抽屜與 `/search` 頁共用一致的搜尋與語言選擇體驗。
3. 語言列表只顯示 `expression_count > 0` 的語言。
4. 在本機保存最近選過的三種搜尋語言，並按最近使用順序置頂。
5. 搜尋 URL 明確保存查詢與語言，支援重新整理、分享及上一頁／下一頁。
6. 維持既有 Atlas 視覺系統、鍵盤操作與基本無障礙。

## 非目標

- 不修改介面語言切換器。
- 不改變 mapping graph 的目標語言篩選。
- 不改變貢獻表單或其他非搜尋用途的語言選擇器。
- 不新增資料表、使用者偏好 API 或登入帳號同步。
- 不改變詞句搜尋的匹配、排序與分頁語意。

## 使用者體驗

### 共用控制

詞句搜尋採一體式工具列：左側為單選語言下拉，右側為搜尋輸入框。兩者共用外框與 focus 語言，透過分隔線表達「先指定語言，再輸入詞句」的關係，而不是兩個互不相關的表單欄位。

- 語言已選取時顯示本地化名稱；空間不足時名稱單行省略。
- 語言代碼以較淡的等寬字顯示，作為名稱相近時的辨識輔助。
- 搜尋框沿用搜尋圖示、`/` 快捷鍵與既有 placeholder。
- 頁面版可採較寬尺寸，導覽列採緊湊尺寸；結構、狀態與互動保持一致。
- 選擇語言不立即送出導覽列搜尋；使用者提交關鍵字時才前往結果頁。
- `/search` 頁已存在查詢時，變更語言後沿用現行行為立即重新搜尋。

### 語言下拉

下拉列表分為兩段：

1. 「最近使用」：最多三種，按最近選取時間由新到舊排列。
2. 「所有語言」：排除已出現在最近使用段的語言後，按目前介面語言下的顯示名稱排序；名稱相同時按 canonical language code 排序。

每列顯示語言名稱、語言代碼與詞句數。零詞句語言不得出現。若近期紀錄中的語言已不存在或詞句數變成零，載入資料後忽略該紀錄，不把它加入列表或設為預設值。

選取語言時立即更新最近使用紀錄，即使使用者尚未送出搜尋。重複選取會把該語言移到第一位，不產生重複項目；紀錄永遠裁切為三種。

### 初始狀態與 URL

語言初始值依下列優先順序決定：

1. URL 中有效的 `lang`。
2. 最近使用列表中的第一種有效語言。
3. 未選取狀態。

導覽列送出後前往 `/search?q=<query>&lang=<code>`。若尚未選擇語言，表單不導覽，將 focus 移到語言選擇器並顯示簡短的行內提示。空白查詢維持既有的不送出行為。

`/search` 頁的 URL 同步仍使用 `q` 與單一 `lang`；本改動不引入多語言搜尋。

## 版面與響應式設計

### 寬桌面

導覽列分為左、中、右三個視覺區域：

- 左側：品牌與主要導覽。
- 中間：一體式搜尋工具列。
- 右側：貢獻、介面語言與登入狀態。

在空間足夠時，中間區以視窗水平中心為基準，而不是以左右剩餘空間的中心為基準。工具列使用受限制的響應式寬度，避免過長；左右區域保持既有順序與樣式。

### 中等寬度

在桌面內容不足以維持真正置中時，搜尋工具列縮小到允許寬度，仍保持語言與查詢兩段可辨識。不得與左右導覽重疊；必要時提早切換為行動導覽，而不是壓縮到不可操作。

### 行動版

搜尋仍位於現有抽屜頂部，改為上下排列：語言選擇在上、搜尋輸入在下。控制目標至少 44px，高度與字級避免 iOS 自動縮放。抽屜內與搜尋頁使用同一份語言資料及最近使用紀錄。

## 視覺規範

- 沿用 `web/src/assets/atlas.css` 的 `--surface`、`--border`、`--accent`、`--muted`、`--mono` 與 `--r`。
- 不新增顏色、陰影或圓角系統。
- 搜尋圖示及下拉箭頭使用 `lucide-vue-next`。
- 導覽列控制高度維持 40px；行動版控制至少 44px。
- focus 使用現有陶土色邊框及柔和外圈，並保持可見。
- 下拉維持低圓角、紙白表面與現有選項 hover／active 色。

## 元件與責任邊界

### `ExpressionSearchControls`

新增詞句搜尋專用的共用控制元件，由導覽列、行動版抽屜與 `/search` 頁組合使用。

責任：

- 呈現單一語言選擇器與搜尋輸入。
- 接收並更新 `query`、`language`。
- 提供 `compact` 與 `page` 視覺變體，但不自行導覽或呼叫搜尋 API。
- 暴露 submit 與 language-change 事件，由頁面或導覽列決定後續行為。
- 顯示語言缺失與載入錯誤狀態。

### 搜尋語言 composable

擴充既有 `useSearchLanguages`，集中管理：

- 可搜尋語言載入狀態。
- `expression_count > 0` 過濾。
- 最近三種紀錄的讀取、驗證、去重、裁切與保存。
- 最近使用與其餘語言的穩定分段排序。
- 依介面語言重新取得名稱並重新排序。

元件不得各自複製排序或 localStorage 邏輯。

### 消費端

- `TopNav` 只負責決定是否顯示搜尋、處理提交導覽、抽屜開關與 `/` 聚焦。
- `Search` 只負責 URL 同步、查詢請求、結果與錯誤狀態。
- 現有一般用途 `LanguageSelect` 不承擔詞句數門檻與最近搜尋排序，避免影響 graph、貢獻等不同語意的選擇器。

## 資料來源與流程

1. 共用 composable 透過前端 API client 呼叫 `GET /api/v2/languages?sort=alpha`。
2. composable 依分頁資訊載入所有內容語言，並保留 `expression_count > 0` 的項目。現有 endpoint 亦可能回傳只有 locale、沒有詞句的語言，因此前端仍需執行明確門檻過濾。
3. composable 讀取 `localStorage['langmap.search.languages']`，只保留目前可用且不重複的前三個代碼。
4. 最近使用項目按儲存順序呈現，其餘項目用本地化名稱及代碼穩定排序。
5. 使用者選取語言後立即更新記憶；提交時把語言與查詢寫入 URL。
6. `/search` 頁從 URL 還原狀態並透過既有 `/expressions/search` 契約取得結果。

本改動不需要 backend schema 或 API 契約變更。

## 載入、錯誤與空狀態

- 載入語言時，選擇器顯示非阻塞 loading 狀態並暫停提交。
- API 失敗時顯示本地化行內錯誤；保留查詢文字，讓使用者可重試。
- 沒有任何 `expression_count > 0` 的語言時顯示明確空狀態，不退回完整 registry。
- localStorage 不可用或內容損壞時退回記憶體狀態，不阻止搜尋。
- URL 的 `lang` 無效時不發出搜尋請求，改為未選取狀態並顯示語言提示。
- 介面語言變更後重新解析顯示名稱及排序，不改變已選語言代碼。

## 無障礙與鍵盤

- 整體保留 `role="search"`，搜尋輸入與語言選擇各自具有清楚的 accessible name。
- 語言選擇器採 combobox/listbox 語意，維護 `aria-expanded`、`aria-controls`、`aria-activedescendant` 與選項狀態。
- 支援方向鍵移動、Enter 選取、Escape 關閉及 Tab 正常離開。
- 下拉分段標題不作為可選項；螢幕閱讀器可理解分段名稱。
- 所有互動控制有可見 focus，行動版觸控目標至少 44px。
- `/` 快捷鍵只在使用者不位於其他輸入控制時聚焦詞句搜尋框。

## 驗收與測試

### 單元與元件測試

- 只保留 `expression_count > 0` 的語言。
- 最近選擇去重、移到首位並裁切為三種。
- 損壞、失效或零詞句的儲存紀錄被安全忽略。
- 最近三種置頂，其餘按本地化名稱與代碼穩定排序。
- 語言選擇後立即保存；localStorage 失敗不使元件崩潰。
- TopNav 提交產生同時含 `q` 與 `lang` 的搜尋 URL。
- `/search` 正確採用 URL 語言，沒有 URL 語言時採用最近的有效語言。
- 語言缺失或無效時不呼叫搜尋 API，並顯示行內提示。
- combobox 鍵盤操作與 ARIA 狀態正確。

### 視覺與流程驗證

- 執行 `cd web && npm run build`。
- 在寬桌面檢查搜尋工具列相對視窗置中，左右操作沒有位移或重疊。
- 在中等寬度檢查工具列縮放與行動導覽切換點。
- 在行動 viewport 檢查上下排列、44px 觸控目標、長語言名稱與下拉不溢出。
- 驗證導覽列選取語言、送出、抵達搜尋頁、變更語言及重新整理後狀態一致。
- 驗證最近三種跨導覽列、抽屜與搜尋頁同步，第四種選擇會移除最舊項目。

## 相容與回退

- 沿用既有 `langmap.search.languages` 儲存鍵；既有最多六種的資料在讀取時安全裁切為三種，不需 migration。
- URL 維持既有 `q` 與 `lang` 參數，不破壞既有搜尋連結。
- 若需回退，可移除共用控制並恢復原 TopNav／Search 組合；localStorage 中的三項紀錄仍與舊格式相容。

## 完成條件

當三個詞句搜尋入口使用相同控制、語言列表只含有詞句的語言、最近三種排序與記憶正確、桌面置中且桌面／行動驗證通過時，本功能才算完成。
